<KbCard num="1" title="重点逻辑1：家装与工程共用后端代码通过参数区分 共用代码">
<KbQuote>家装折扣政策申请和工程折扣政策申请业务逻辑高度相似，共用同一套后端Service/Controller/Entity代码，通过参数区分业务类型</KbQuote>

**具体逻辑**：

- 1、前端列表查询时固定传入 `isMakt=0`、`suitableType='special'`，后端据此过滤家装专项折扣政策数据
- 2、前端保存/提交时固定传入 `isMakt=0`、`suitableType='special'`，后端据此确定编码规则为 `EPM_DISCOUNT_POLICY_JZ`（家装），工程为 `EPM_DISCOUNT_POLICY_GC`
- 3、家装销售渠道默认为 `3`（家装），且不可编辑；工程销售渠道可选
- 4、家装业务类型值集使用 `AE.EPM.HOME.BUSINESS_TYPE2`，工程使用 `AE.EPM.BUSINESS_TYPE`
</KbCard>

<KbCard num="2" title="重点逻辑2：价值链自动计算 自动计算">
<KbQuote>价值链反映产品折后利润率，是审批时的重要参考指标</KbQuote>

**具体逻辑**：

- 1、坎级价值链 = (折后单价 - 成本单价) / 折后单价，保留4位小数
- 2、当优惠方式为"折扣"时，折后单价 = 标准单价(不含安装) × 折扣率
- 3、当优惠方式为"特价"时，折后单价 = 特价；同时反算折扣率 = 特价 / (标准单价(不含安装) × 出厂折扣率)，保留7位小数
- 4、整单价值链 = (折后总价 - 成本总价) / 折后总价，保留4位小数
</KbCard>

<KbCard num="3" title="重点逻辑3：政策分析说明自动生成 自动计算">
<KbQuote>按生命状态汇总产品折扣情况，供审批人快速了解政策整体折扣水平</KbQuote>

**具体逻辑**：

- 1、仅对申请类型为"产品"的行，按生命状态分组统计产品数量和平均折扣率
- 2、生成格式如："生命状态XX状态的数量N个，平均折扣为0.XXX；"
</KbCard>

<KbCard num="4" title="重点逻辑4：警戒线提醒 自动计算">
<KbQuote>当坎级折扣率低于生命状态对应的告警水位时，自动标记警戒线提醒，提示审批人关注</KbQuote>

**具体逻辑**：

- 1、根据值集 `AE.DISCOUNT_CONTROL_WARN_LINE` 配置的告警水位，按生命状态匹配
- 2、当坎级折扣率 &lt; 告警水位值时，在坎级扩展表中记录告警描述信息
</KbCard>

<KbCard num="5" title="重点逻辑5：阶梯政策区间冲突校验 前端校验">
<KbQuote>同一产品下的阶梯政策起订量和封顶量区间不能重叠，确保每个数量区间对应唯一的折扣/特价</KbQuote>

**具体逻辑**：

- 1、修改起订量或封顶量时，实时校验与同一产品下其他阶梯政策行区间是否冲突
- 2、冲突条件：A≤C且B≥C，或A≤D且B≥D，或A≥C且B≤D，或A≤C且B≥D（A/B为当前行起订量/封顶量，C/D为比较行起订量/封顶量）
</KbCard>

<KbCard title="导入">
<KbSubTitle>前置约定</KbSubTitle>


- 文件样例：折扣政策导入模板.xlsx
- 格式：.xlsx 或 .xls
- 文件大小：无特殊限制


<KbSubTitle>字段映射</KbSubTitle>


| 字段含义 | 是否必输 | 字段格式 | 重复判定字段 |
|---------|---------|---------|------------|
| 产品编码 | 是 | 文本 | 是（与表格中已有产品编码重复则跳过） |
| 产品型号 | 按申请类型 | 文本 | 是（申请类型=型号时） |
| 申请类型 | 是 | 数值(1/2/3) | 否 |
| 优惠方式 | 是 | 数值(1/2) | 否 |
| 起订量 | 是 | 正整数 | 否 |
| 封顶量 | 是 | 正整数 | 否 |
| 折扣率 | 优惠方式=折扣时 | 小数(3位) | 否 |
| 特价 | 优惠方式=特价时 | 小数(3位) | 否 |


<KbSubTitle>处理逻辑</KbSubTitle>


- **校验逻辑**：导入前如果单据未保存，先自动保存头信息再导入；校验文件格式必须为.xlsx/.xls
- **导入逻辑**：调用后端 `/epm-discount-policy/importProduct` 接口，传入discountPolicyId、channel、currency、divisionId等参数；返回数据追加到产品明细表格，同时为每个产品创建对应的阶梯政策记录
- **重复处理策略**：跳过（已存在的产品编码不覆盖，提示警告）
- **性能方案**：同步导入


<KbSubTitle>异常与结果约定</KbSubTitle>


- 部分成功/失败时的处理：重复产品编码跳过并提示警告，新增成功数量提示成功
- 结果反馈机制：成功提示"导入成功，新增N条数据"；重复提示"产品编码已存在表格中，不能覆盖"


<KbSubTitle>运维保障</KbSubTitle>


- 日志记录：后端LOGGER记录导入参数和结果
- 断点续传/重试机制：不支持，需重新上传整个文件

<KbSubTitle>校验1：产品行不能为空 —— 确保政策至少有一条产品明细</KbSubTitle>

- 第1点：新建时产品行列表为空则报错
- 第2点：所有产品行都被删除（_status=delete）也报错

<KbTip>阻断性报错</KbTip>

```sql
SELECT COUNT(*) FROM EPM_DISCOUNT_POLICY_ITEM WHERE DISCOUNT_POLICY_ID = :discountPolicyId AND _status != 'delete'
```

<KbSubTitle>校验2：申请类型互斥校验 —— 全产品类型与产品/型号类型不能同时存在</KbSubTitle>

- 第1点：产品行中同时存在申请类型=3(全产品)和申请类型=1(产品)或2(型号)时报错

<KbTip>阻断性报错</KbTip>

```sql
SELECT APPLICATION_TYPE, COUNT(*) FROM EPM_DISCOUNT_POLICY_ITEM WHERE DISCOUNT_POLICY_ID = :discountPolicyId GROUP BY APPLICATION_TYPE
```

<KbSubTitle>校验3：封顶数量校验 —— 专项政策下封顶数量逻辑一致性</KbSubTitle>

- 第1点：封顶数量校验=否时，单个经销商封顶数量必须为空
- 第2点：封顶数量校验=是时，单个经销商封顶数量必须为正整数

<KbTip>阻断性报错</KbTip>

```sql
SELECT ITEM_CODE, CAPPING, CUSTOM_CAPS_NUMBER FROM EPM_DISCOUNT_POLICY_ITEM WHERE DISCOUNT_POLICY_ID = :discountPolicyId
```

- 第1点：家装(isMakt!=2且suitableType=special)时，对新增状态的产品行调用verifyNewProd校验新品

<KbTip>阻断性报错</KbTip>

```sql
SELECT ITEM_CODE, NEW_PROD_FLAG FROM EPM_DISCOUNT_POLICY_ITEM_EXT WHERE DISCOUNT_POLICY_ID = :discountPolicyId
```

<KbSubTitle>校验5：阶梯政策起订量/封顶量/折扣率/特价必填 —— 确保阶梯政策数据完整</KbSubTitle>

- 第1点：每条阶梯政策的起订量必填
- 第2点：优惠方式=折扣时折扣率必填，优惠方式=特价时特价必填
- 第3点：封顶量必填

<KbTip>toast提醒</KbTip>

```sql
SELECT l.ITEM_CODE, il.MINIMUM_QTY, il.CAPPING_QTY, il.DISCOUNT_RATE, il.SPECIAL_OFFER

    JOIN EPM_DISCOUNT_POLICY_ITEM l ON il.DISCOUNT_POLICY_ITEM_ID = l.DISCOUNT_POLICY_ITEM_ID
    WHERE il.DISCOUNT_POLICY_ID = :discountPolicyId
    AND (il.MINIMUM_QTY IS NULL OR il.MINIMUM_QTY = 0 OR il.CAPPING_QTY IS NULL OR il.CAPPING_QTY = 0)
```

- 第1点：有批次开始日期无批次结束日期，或反之，均报错

### 状态机

<KbSubTitle>状态机流转图</KbSubTitle>


```text
[NEW 新建] ──提交──→ [RUN 审批中] ──审批通过──→ [APPROVED 审批通过]
     │                    │
     │                    ├──审批拒绝──→ [REJECTED 审批拒绝]
     │                    │
     │                    └──撤回──→ [WITHDRAW 已撤回]
     │
     └──删除──→ (删除)

[REJECTED 审批拒绝] ──重新编辑提交──→ [RUN 审批中]
[WITHDRAW 已撤回] ──重新编辑提交──→ [RUN 审批中]
[RUN 审批中] ──终止──→ [INTERRUPT 终止]
```
