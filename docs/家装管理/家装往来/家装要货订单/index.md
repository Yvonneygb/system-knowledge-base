<KbCard num="1" title="重点逻辑1：家装类型业务与价格类型联动 类型联动">
<KbQuote>家装要货订单区分直销和经销两种业务模式，不同模式下的价格类型选择和字段联动逻辑不同</KbQuote>

**具体逻辑**：

- 1、家装类型业务为"直销"时，价格类型自动设为"折扣单"(1)，且不可修改；自动弹出合同选择弹窗
- 2、家装类型业务为"经销"时，价格类型可选折扣单(1)、折扣政策(2)、价目表(3)
- 3、切换家装类型业务时，清空所有关联字段(客户、交易公司、折扣单、折扣政策、项目、收货人等)和产品明细行
- 4、切换价格类型时，清空折扣信息、政策信息、项目信息、合同信息、收货信息等关联字段和产品明细行
- 5、直销模式下，选择合同后自动带出客户、项目、交易公司、折扣单等信息；若合同关联多个折扣单，弹窗让用户选择
</KbCard>

<KbCard num="2" title="重点逻辑2：期望到达日期与订单类型自动计算 日期联动">
<KbQuote>根据期望到达日期自动判断订单类型(常规/计划)，确保订单日期合规</KbQuote>

**具体逻辑**：

- 1、当月25号前下单，期望到达日期为当月→常规订单(1)；期望到达日期为后续月份→计划订单(2)
- 2、当月25号后下单，非电商渠道且产品线为瓷砖可下常规订单(期望到达日期为当月)；其他类型只能选次月及以后
- 3、电商渠道期望到达日期限制为6个月内；其他渠道限制为3个月内
- 4、期望到达日期不能超过一年
- 5、计划订单时，期望到达日期不能晚于折扣政策有效期或折扣有效期
- 6、海外事业部(organizationId=111)且境外注册出口经销商时，订单类型为13(常规)或14(计划)
</KbCard>

<KbCard num="3" title="重点逻辑3：产品生命状态校验 生命状态">
<KbQuote>下单前校验产品生命状态，避免下达已淘汰或不可销售的产品订单</KbQuote>

**具体逻辑**：

- 1、Z8状态不允许下达订单，阻断性报错
- 2、Z6状态为计划淘汰中，弹窗警告但允许继续
- 3、S6状态为产品进入售后阶段，弹窗警告但允许继续
- 4、Z7状态为有库存数量发完即止，弹窗警告但允许继续
</KbCard>

<KbCard num="4" title="重点逻辑4：紧急行数限制 紧急限制">
<KbQuote>限制紧急订单行数，避免大量紧急订单影响生产计划</KbQuote>

**具体逻辑**：

- 1、常规订单不允许加紧急标记
- 2、计划订单可加紧急标记，但紧急行数不能超过总行数的1/5(向上取整)
- 3、公式：可加紧急行数=向上取整(明细行数/5)
</KbCard>

<KbCard num="5" title="重点逻辑5：家装与工程/样品共用后端代码 共用代码">
<KbQuote>家装要货订单、工程要货订单、样品要货订单共用同一套后端代码，通过isHome参数区分</KbQuote>

**具体逻辑**：

- 1、家装标识isHome=2，工程为其他值，样品另有区分
- 2、家装使用编码规则AE.EPM_PROJECT_HOME_BILL_HEAD生成要货单号
- 3、家装OA对象类型为9020，OA单据名称为"折扣政策要货"(BillnameEnum.ZKZCYH)
- 4、家装+直签+合同限定+折扣单类型时，不执行可下单数量的扣减/返还
- 5、家装+折扣政策类型保存时需校验并获取政策产品价格
- 6、家装+折扣单类型提交时校验报备是否生效
- 7、家装提交时更新项目阶段(首次→已下首单，二次→持续供货中)
- 8、家装价目表或折扣单类型不需要送签OA(直接生成CRM订单)
</KbCard>

<KbCard title="保存校验">
<KbSubTitle>校验1：本次下单数量必须大于0 —— 确保每条明细行都有有效的下单数量</KbSubTitle>

- 遍历所有非删除状态的明细行，检查qtyBill是否大于0
- 收集所有异常行号

<KbTip>toast错误提醒"申请数量必须大于0，以下行不合法：第X、Y行"</KbTip>

```sql
SELECT LINE_SEQ, QTY_BILL FROM SA_OUT_BILL_LINE WHERE SA_OUT_BILL_HEAD_ID = ? AND (QTY_BILL IS NULL OR QTY_BILL <= 0)
```

<KbSubTitle>校验2：紧急行数限制 —— 确保紧急标记使用合理</KbSubTitle>

- 常规订单(billType=1或13)不允许加紧急标记
- 计划订单紧急行数不能超过总行数的1/5(向上取整)
- 公式：可加紧急行数=向上取整(明细行数/5)

<KbTip>toast错误提醒"只有计划订单可以加紧急"或"紧急行数过多..."</KbTip>

```sql
SELECT COUNT(*) AS TOTAL, SUM(CASE WHEN URGENCY = 2 THEN 1 ELSE 0 END) AS URGENT_COUNT
    FROM SA_OUT_BILL_LINE WHERE SA_OUT_BILL_HEAD_ID = ?
```

<KbSubTitle>校验3：整箱包装数校验 —— 确保下单数量是整箱包装数的倍数</KbSubTitle>

- 仅经销商用户(userType=D)时校验
- 价格类型为折扣政策(2)或价目表(3)，且产品线为卫浴(1)，且销售渠道为家装(1)或零售(3)时校验
- 整箱包装数不为0或空时，下单数量必须是整箱包装数的倍数

<KbTip>toast错误提醒"下单数量必须是整箱包装数的倍数，第X、Y行"</KbTip>

```sql
SELECT L.LINE_SEQ, L.QTY_BILL, L.PACKAGE_NUMBER
    FROM SA_OUT_BILL_LINE L
    JOIN SA_OUT_BILL_HEAD H ON H.SA_OUT_BILL_HEAD_ID = L.SA_OUT_BILL_HEAD_ID
    WHERE H.SA_OUT_BILL_HEAD_ID = ?
    AND L.PACKAGE_NUMBER > 0 AND L.QTY_BILL % L.PACKAGE_NUMBER != 0
```

<KbSubTitle>校验4：产品生命状态校验 —— 确保不下达已淘汰产品订单</KbSubTitle>

- 调用updateSmState接口获取所有明细行的产品生命状态
- Z8状态不允许下达订单，阻断性报错
- Z6(计划淘汰)、S6(售后阶段)、Z7(有库存发完即止)状态弹窗警告，用户确认后可继续

<KbTip>Z8→阻断性报错；Z6/S6/Z7→弹窗确认</KbTip>

```sql
SELECT L.LINE_SEQ, L.ITEM_CODE, L.SM_STATE FROM SA_OUT_BILL_LINE L WHERE L.SA_OUT_BILL_HEAD_ID = ? AND L.SM_STATE IN ('Z6', 'Z7', 'Z8', 'S6')
```

<KbSubTitle>校验5：折扣政策数据获取校验 —— 确保折扣政策产品价格有效</KbSubTitle>

- 价格类型为折扣政策(2)时，调用getPolicyItemData接口获取政策产品价格
- 更新明细行的折扣率、折后单价、折后金额等字段
- 获取失败则阻断保存

<KbTip>阻断性报错</KbTip>

```sql
SELECT * FROM EPM_DISCOUNT_POLICY_ITEM WHERE DISCOUNT_POLICY_ID = ? AND IS_HOME = 2
```

      <strong style="color:#7C3AED;">原因：</strong>CRM编辑标记=2时，期望到达日期变更不触发订单类型自动计算<br>
